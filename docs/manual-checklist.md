# 手動驗收清單（實機測試）

自動測試（`npm test`）與檢查（`npm run audit`）已涵蓋計算與格式；下面是需要人在真的裝置上確認的項目。部署到 GitHub Pages 後，用 https 網址測試。

## A. 手機（iPhone Safari、Android Chrome 各一台）

- [ ] 畫面沒有左右捲動，文字沒有被切掉。
- [ ] 每個按鈕都好按（手指點得到，不會按錯旁邊的）。
- [ ] 明度滑桿可以拖動，選色圓與色碼會跟著變。
- [ ] 「輸入色碼」：輸入 `#E36F4F` 後推薦會更新；輸入錯的色碼會出現提示。
- [ ] 推薦卡片可以左右滑動，點選後預覽跟著換。
- [ ] 「從圖片取色」：可以從相簿選照片，出現 5 個代表色，點一個後變成主色。
- [ ] 「複製」按鈕：貼到記事本是正確的色碼，畫面有「已複製」提示。
- [ ] 大眾模式「分享色票卡」：手機跳出分享選單，可以存到相簿或傳給 LINE；圖片內容正確。
- [ ] 「加入主畫面」：Android Chrome 選單「安裝應用程式」、iPhone Safari「分享 → 加入主畫面」，桌面圖示正常（不是白底或被切掉）。
- [ ] 從主畫面打開後，開飛航模式再打開一次，仍可使用（離線）。

## B. 電腦（Chrome 或 Edge）

- [ ] 寬螢幕是兩欄版面，推薦卡片在下方。
- [ ] 大眾模式「下載色票卡」：下載的 PNG 打得開，內容正確。
- [ ] 依 `docs/deploy.md`「驗證離線可用」的步驟，離線也能打開。

## C. 老師模式

- [ ] 切到老師模式，**選色不變**；切回大眾模式，風格選擇還在。
- [ ] 四個場景都能切換，預覽版面跟著換；選「學習單」時預覽自動變成黑白。
- [ ] 投影模式打開：字級變大（簡報標題 40、內文 24），出現「適合投影嗎」檢查。
- [ ] 字級「−」一直按會停在最小值，按鈕變成不能按。
- [ ] 「黑白列印」「紅色弱」「綠色弱」「藍色弱」都能切換，預覽顏色有變化。
- [ ] 實際把「學習單」預覽的配色用黑白印表機印一張，主色和輔色看得出差別。
- [ ] 用投影機投出簡報預覽，坐在教室最後一排看得清楚文字。

## D. 收藏

- [ ] 「加入收藏」後，在「我的收藏」看得到；重新整理網頁後仍在。
- [ ] 同一組配色再按一次「加入收藏」，提示「已經在收藏裡了」。
- [ ] 可以改名、套用、刪除。
- [ ] 用無痕視窗開啟：按「加入收藏」不會當掉（可能提示無法儲存，屬正常）。

## E. 複製給 AI 簡報用（階段 4B 手動驗證）

在老師模式的「匯出」區操作，至少用兩個 AI 工具（例如 ChatGPT、Claude、Gemini）各做一次：

1. 選「完整提示詞」，按「複製給 AI 簡報用」。
2. 貼到 AI 工具，把「（請填入主題）」改成真的主題，例如「水的三態」。
3. 請 AI 產生簡報（或產生可貼進 Google 簡報的內容）。
4. 檢查產生的結果：
   - [ ] 使用的顏色是 YAML 裡的 5 個色碼，沒有多出別的顏色。
   - [ ] 文字使用 `text` 色，不是純黑。
   - [ ] 標題、內文字級與 YAML 一致（例如 36 pt、20 pt）。
   - [ ] 每頁重點不超過 YAML 的 `max_points_per_slide`。
   - [ ] 使用台灣繁體中文與台灣用語。
5. 再選「YAML 設計規格」複製一次，貼給 AI 並加一句「請依這份規格做一份介紹○○的簡報」，檢查結果同上。
6. 記錄哪個 AI 工具遵守得最好；之後向 1–2 位老師蒐集回饋（SPEC 6.1 的價值假設）。

## F. 安全

- [ ] 部署前 `npm run audit` 全部通過。
- [ ] GitHub repository 的檔案列表裡沒有 `reference/`、`.env`。
- [ ] 打開網站時按 F12 → Network，除了自己網址的檔案，沒有任何其他網域的請求。
